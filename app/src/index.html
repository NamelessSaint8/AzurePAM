Readiness

The engine needs PowerShell 7 + the Microsoft.Graph module to run an assessment. The Az.* set is optional; without it Defender / Azure Policy degrade gracefully. Missing items can be installed inline (CurrentUser scope); some local-machine checks also need administrator rights — use Restart as administrator when prompted.

    Choose how to sign in and which assessment modules to run. Results stream live as the PowerShell engine produces them.

    Example: contoso.onmicrosoft.com, contoso.com (verified custom domain), or the tenant GUID. The value is used to label the report; the signed-in account determines which tenant is actually queried.

    Sign-in

    Access Review (UAR)

    A campaign runs on its own — no assessment modules, no unified report. Open one, let the reviewer fill review-worksheet.csv in Excel, then close it to verify the decisions and render the report. The campaign folder is audit evidence, so it lives outside the temporary run folder and is remembered between launches.

    1. Open new campaign — writes the roster, review-worksheet.csv and a hashed manifest.
    2. Open worksheet and set Decision on every Access row to one of Certify, Revoke, Modify or Investigate. Add Notes where useful.
    3. Fill the three SignOff rows — put ReviewerName, ReviewerTitle and SignOffDate (YYYY-MM-DD) in each row's Notes column.
    4. Save as CSV. Do not add, remove or reorder rows or columns — the worksheet is checked against the baseline.
    5. Make the access changes yourself in Entra ID / PIM. EntraChecks is read-only and never revokes anything — a Revoke decision records intent, it does not act.
    6. Select the campaign and Close campaign. It re-reads the tenant and checks each decision against what actually changed, flagging NOT_REMEDIATED where a revoke never happened, then renders the report.

    Close before making the changes and every revoke comes back NOT_REMEDIATED. A close that fails writes nothing and leaves the campaign Open — fix and close again.

      EntraChecks writes the remediation script and its plan — it never runs them. Read the script, then run it yourself. Needs a Closed campaign, and is off until you set AccessReview.EnableRemediation to true in config\entrachecks.config.json.
